# CLAUDE.md

## Project

**Retail Inventory Decision Support System**, a two-person team project.

- **Person 1** builds the SQLite database, the rule engine, the agent state machine, and the Streamlit dashboard.
- **Person 2 (this repo's owner)** builds only the pure-Python decision backend: the `decision_engine` package.

### Person 2 scope

1. Synthetic sales data generation (`decision_engine/data_generator.py`)
2. Stockout risk estimation using Bayes' Theorem (`decision_engine/bayes_risk.py`)
3. Order quantity optimization using Utility Theory, plus the economic review period (`decision_engine/optimizer.py`)
4. An evaluation simulation comparing this system to a static reorder policy (`decision_engine/evaluation.py`)
5. Unit tests (`tests/`)
6. The daily wrapper `recommend_order` (`decision_engine/recommend.py`), which Person 1's agent calls once per product per day; the agent orders its `recommended_qty`
7. `effective_inventory_position` (`decision_engine/inventory.py`), used by both policies in the evaluation

### Integration with Person 1

Person 1 imports the `decision_engine` package. They first integrate against `decision_engine/mock.py`, then switch to the real functions, which **must keep the same signatures and return formats** as the mocks. `decision_engine/interface.md` documents the contract. Any change to a public signature must be reflected in `mock.py` and `interface.md` together.

## Key definitions

- **`current_stock` / inventory position** = units on hand + units already ordered but not yet delivered. Person 1's agent must pass this, otherwise it will reorder the same item every day while an order is in transit.
- **`review_period_days`** = the planned order cycle: days from when this order arrives until the next order can arrive. `recommend_order` uses the economic (EOQ) cycle by default; the agent still runs daily, and recommend_order's when-to-order rule makes it wait on most days. Lower-level functions default to 1.
- **Order horizon** = `lead_time_days + review_period_days`. An order placed today must cover demand until the following order can arrive.
- **Timing**: the decision is made at the start of `current_date`, before that day's sales. Lead-time window = `current_date` through `current_date + lead_time_days - 1`; order-horizon window = `current_date` through `current_date + lead_time_days + review_period_days - 1`.
- **`stockout_penalty`** = goodwill cost per unit short, ON TOP OF the lost margin. Lost margin is already captured because revenue only counts units sold.
- **`spoilage_cost`** = extra disposal cost per spoiled unit, ON TOP OF losing the unit's purchase cost. Default 0.
- **`order_cost`** = fixed cost per order placed for one product (delivery, handling, admin), regardless of quantity.

## Conventions

- **Pure functions only.** No database access, no SQL, no Streamlit, and no file I/O inside core functions. Data comes in as arguments (pandas DataFrames or plain values).
- **Return types:** all public functions return plain Python `dict`s or pandas `DataFrame`s. Dict values must be JSON-serializable built-in types. Convert numpy ints and floats to `int` and `float`.
- **Type hints and docstrings** on every public function. Docstrings state assumptions explicitly.
- **Randomness:** any function that uses randomness takes a `seed` argument and uses `numpy.random.default_rng(seed)`.
- **Tests** use pytest and live in `tests/`.
- **Python 3.10+.**

## Layout

```
decision_engine/
  __init__.py
  interface.md       # public API contract shared with Person 1
  mock.py            # mock functions with the real signatures
  data_generator.py  # synthetic sales history
  bayes_risk.py      # stockout risk via Bayes' Theorem
  optimizer.py       # order quantity via Utility Theory; economic review period
  recommend.py       # recommend_order: the agent's daily call (how much + whether today)
  inventory.py       # effective_inventory_position for perishable batches
  evaluation.py      # simulation vs. static reorder policy
data/
  sample_products.csv
tests/
  fixtures/          # pre-robustness snapshot: defaults must reproduce it exactly
scripts/
  preview_data.py    # prints demand by weekend/promo group
  preview_risk.py    # posterior group rates and stockout risk by window
  preview_order.py   # order quantities, linear vs. risk-averse
  evaluation_report.py  # baseline vs. DSS vs. ablation over test seeds 0-19
  robustness_report.py  # tuned baseline, cost sensitivity, misspecified demand (parallel)
requirements.txt
```
